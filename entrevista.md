Desafío técnico — Fullstack Developer
Objetivo
El objetivo de este desafío es conocer tu forma de analizar un problema, priorizar el alcance, construir una
solución y comunicar tus decisiones.
No buscamos una solución productiva ni esperamos que dediques más tiempo del indicado. Valoraremos
tanto lo implementado como tu capacidad para explicar lo que dejarías pendiente y cómo lo abordarías.
Tiempo disponible
Plazo de entrega: 2 días.
Dedicación máxima esperada: 4 horas.
No es necesario completar todos los puntos.
Si se cumple el tiempo disponible, puedes detener el desarrollo y documentar lo que quedó
pendiente.
Caso
Se necesita una aplicación sencilla para registrar y gestionar solicitudes internas.
Cada solicitud debe contener, como mínimo:
Título.
Descripción.
Nombre o correo del solicitante.
Prioridad: baja, media o alta.
Estado: pendiente, en proceso o completada.
Fecha de creación.
Funcionalidades principales
La solución debe permitir:
Crear una solicitud desde el frontend.
Listar las solicitudes registradas.
Visualizar el estado y prioridad de cada solicitud.
Cambiar el estado de una solicitud.
Validar los campos obligatorios.
Mostrar mensajes comprensibles cuando ocurra un error.

Backend
Debe incluir al menos un servicio backend con endpoints reales.
Como referencia, pueden implementarse los siguientes:
Crear una solicitud.
Listar solicitudes.
Actualizar el estado de una solicitud.
Puedes modificar esta propuesta si consideras que existe un diseño más adecuado.
Frontend
Debe incluir una interfaz sencilla que permita:
Registrar una solicitud.
Consultar las solicitudes existentes.
Identificar visualmente su estado y prioridad.
Cambiar el estado de una solicitud.
Mostrar estados de carga, éxito o error.
No se evaluará diseño gráfico avanzado.
Persistencia
Puedes utilizar:
Una base de datos relacional o no relacional.
Un archivo local.
Persistencia en memoria.
La alternativa seleccionada debe quedar explicada en el README, incluyendo sus limitaciones.
Consideraciones técnicas
Se espera que la solución incluya:
Separación clara entre frontend, backend y lógica de negocio.
Validaciones básicas.
Manejo controlado de errores.
Código legible y organizado.
Uso de Git.
Instrucciones para ejecutar el proyecto.
Al menos una prueba automatizada sobre una parte relevante.

Alcance opcional
Los siguientes puntos son opcionales y no entregan una ventaja automática:
Autenticación.
Despliegue cloud.
Contenedores.
Procesamiento asíncrono.
CI/CD.
Diseño visual avanzado.
Cobertura extensa de pruebas.
Es preferible entregar una solución pequeña y bien explicada antes que agregar complejidad sin una
justificación clara.
Uso de inteligencia artificial
Se permite utilizar herramientas de inteligencia artificial como apoyo.
Durante la presentación debes explicar brevemente:
Para qué las utilizaste.
Qué partes revisaste o modificaste.
Cómo validaste que el resultado fuera correcto.
Entregables
Debes compartir:
Repositorio Git con el código.
README que incluya:
Instrucciones de ejecución.
Tecnologías utilizadas.
Decisiones principales.
Supuestos realizados.
Funcionalidades completadas.
Funcionalidades pendientes.
Mejoras que realizarías con más tiempo.
Evidencia básica de funcionamiento, como capturas o una grabación breve, en caso de que la
solución no esté desplegada.

Presentación
Se realizará una presentación de entre 10 y 15 minutos, seguida de preguntas del equipo.
Durante la presentación esperamos que expliques:
Cómo entendiste el problema.
Qué priorizaste dentro de las cuatro horas.
Cómo organizaste la solución.
Qué decisiones técnicas tomaste.
Qué dificultades encontraste.
Qué mejorarías para llevar la solución a producción.
Cambio de requerimiento
Durante la conversación se planteará un pequeño cambio, por ejemplo:
Agregar un nuevo estado.
Permitir filtrar por prioridad.
Incorporar comentarios en una solicitud.
Notificar al solicitante cuando cambie el estado.
Permitir asignar una solicitud a un responsable.
No será necesario implementarlo en vivo. Se evaluará cómo analizarías el cambio, qué componentes
modificarías y qué impacto tendría.
Criterios de evaluación
Análisis y priorización
Comprensión del problema.
Supuestos realizados.
Uso adecuado del tiempo.
Capacidad para definir un alcance razonable.
Solución técnica
Correctitud funcional.
Organización del código.
Separación de responsabilidades.
Validaciones y manejo de errores.
Decisiones técnicas justificadas.
Calidad de implementación
Legibilidad.
Uso de Git.
